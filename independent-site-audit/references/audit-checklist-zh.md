# 独立站检测清单

把这份清单当作可复用的检查框架。每项可以按 `0` 缺失、`1` 较弱、`2` 合格、`3` 强来打分，并附上证据。

## 数据基础设施

- GA4 核心事件完整触发：`page_view`、`view_item`、`add_to_cart`、`begin_checkout`、`purchase`。
- `purchase` 在 GA4 中被标记为转化事件。
- Meta Pixel、TikTok Pixel、Google Ads Tag 的关键事件与 GA4 漏斗口径基本对齐。
- 广告、邮件、社交、KOL 等渠道的 UTM 命名统一。
- Shopify checkout 或其他跨域/子域结账场景已正确配置跨域追踪。
- 已建立基础漏斗：Sessions → Product Page Views → Add to Cart → Begin Checkout → Purchase。
- 漏斗可以按设备、流量来源、新老用户和落地页拆分。

## 流量质量

- 各来源/媒介的跳出率、转化率和收入贡献被单独查看。
- 品牌词、非品牌付费、社交、邮件、自然搜索的转化表现分开判断。
- 新客与回访客转化率分开判断，回访客通常应明显高于新客。
- 广告素材承诺与落地页首屏内容一致。
- SEO 关键词意图与落地页内容一致。
- 高跳出不是直接归因给页面设计，而是先判断流量意图是否匹配。
- 社交流量跳出高时，优先检查利益点是否足够快、足够清楚。
- 独立站不能直接套用亚马逊/平台的转化判断标准，要考虑信任基础和购买旅程差异。
- 面向欧美市场时，检查页面是否有品牌感、呼吸感、克制营销，而不是国内电商式信息密集。

## 落地页与跳出率治理

- 落地页内容与广告素材、目标受众和渠道心理一致。
- 页面信息按用户决策顺序排布，而不是功能点堆砌。
- 品牌文化融入产品表达，而不是只有参数和促销。
- 页面有清晰排版节奏，视觉重点明确。
- CTA 在关键决策点出现，数量不过多、不分散。
- 付费落地页加载时间不超过 3 秒。
- 高跳出页面按渠道、用户画像、关注点、利益点表达逐项诊断。
- 利益点强化方案经过内测或小流量验证，例如顶部悬浮条、滚动触发提示、右下角弱提示。

## 商业定位与首屏

- 首屏能立刻说明品牌、品类、核心产品或当前 offer。
- Hero 图优先展示真实产品、使用场景或核心卖点，不使用空泛氛围图。
- 页面说清楚目标用户的任务：想解决什么问题、在哪个场景使用、追求什么结果。
- 主 CTA 指向明确商业动作，例如进入 PDP、选择产品、开始测评或加购，而不是模糊跳转。
- 页面解释了为什么要在独立站购买，而不是去 Amazon、平台店、经销商或竞品。
- 首屏 3 秒内能看到核心价值表达，而不是只有促销 banner。
- 首屏 CTA 清晰、可见、可点击，不被弹窗遮挡。
- 超过 60% 用户没有滚动到第二屏时，需要优先检查首屏信息和 CTA。
- 首页到品类页/PDP 的点击率偏低时，需要检查卡片吸引力、CTA 和信息架构。
- 弹窗出现时机、关闭率和遮挡情况被检查；5 秒内弹出且关闭率很高时要谨慎。
- Banner 有符合品牌和业务逻辑的轻交互，不只是无反馈静态图。
- 首页有清晰商品分类、目标导向分区或个性化入口。
- 复杂产品有组装、使用、产品演示等教育内容。

## 商品发现与选品路径

- 导航能暴露主要产品类型、购买意图或使用场景。
- 用户可以按目标、场景、空间、问题、预算或产品类型进入选品。
- 畅销款、推荐款、入门款能降低选择困难。
- 商品卡包含清晰名称、真实图片、关键差异点和直达 PDP 链接。
- SKU 名称、规格和产品 claim 与官方目录一致。
- 品类页默认排序优先服务转化，例如畅销、推荐或主推款，而不是机械按最新排序。
- 筛选器选项实用、位置明显，并有事件追踪。
- 筛选后 0 结果状态有替代推荐或返回路径。
- 品类页到 PDP 点击率低时，要检查商品卡信息、价格、评价、主图和排序。

## 信任与优惠

- 保修、退换货、物流、支付、试用、客服和价格政策在深度结账前可见。
- 所有 claim 使用准确政策语言；证据不足时要弱化表达。
- 社会证明足够具体：评价、媒体、认证、达人、社区、用户案例或真实使用证据。
- 售后路径清楚：FAQ、联系入口、说明书、注册、安装、维修、配件。
- 高风险 claim 在没有当前来源证明前必须移除或改写。

## PDP

- 首页/分类页到 PDP 的入口直接、明显。
- PDP 首屏回答：这是什么、适合谁、核心利益、价格/优惠、配送、退换、主 CTA。
- 桌面端和移动端首屏都能看到价格、CTA 和 3 个以内的核心卖点。
- 产品图有多角度、场景图、尺寸参考；高决策品类优先检查是否有视频。
- 价格、划线价、折扣码和分期逻辑表达清楚。
- 评分、评论数和评论内容在决策区附近可见。
- 免运、退货、保修等保障信息靠近 CTA，而不是藏在页面底部。
- 规格、变体、套装、分期、订阅等选择不应干扰购买判断。
- 变体切换流畅，不因刷新或跳转打断购买。
- 有相关产品、配件或组合推荐，服务于提高客单价而不是干扰主购买。
- 关键内容区不能成为死路，每个主要段落都要有下一步动作。
- H1/H2/H3 层级清晰，正文移动端不低于 14px，PC 不低于 16px，行高不低于 1.5。
- 价格、CTA、库存、配送提示、折扣信息的字号和视觉权重有主次。
- 删除、减号、数量等操作元素不抢购买主流程。
- 移动端与 PC 端分开诊断：移动端重效率和 sticky CTA，PC 端可承载更多品牌叙事和参数。

## 购物车与结账

- 购物车 GMV 被拆为：访问UV x 加购率 x 结算转化率 x 客单价。
- 点击 Add to Cart 后有明确视觉反馈。
- 加购后购物车入口有数量变化或抽屉反馈。
- 购物车展示产品图、名称、价格、数量修改、优惠和小计。
- 运费、税费或可能产生的额外费用尽量在结账前透明。
- 购物车到结账流失率高于 40% 时，优先检查费用、信任、支付和技术问题。
- 购物车有券后价、折扣、本地发货、包邮门槛、差额提示等辅助决策信息。
- 结算按钮附近展示关键利益点，利益点与 CTA 视觉距离足够近。
- 购物车弹窗/侧边栏占比合理，不遮挡过多商品信息，也不因过小导致信息缺失。
- 多品类或多件商品场景下，检查是否需要分类结算或商品筛选。
- 支持 Guest Checkout，不强制注册。
- 必填字段数量克制，超过 8 个必填项需要解释必要性。
- 支持目标市场主流支付方式，例如信用卡、PayPal、Apple Pay、Google Pay、分期。
- 错误提示具体可理解，不只显示 `Error`。
- 首页/PDP 承诺的免运、折扣或分期在结账页保持一致。
- 预计送达时间和物流服务足够清楚。

## 移动端体验

- 移动端首屏保留品牌/产品信号、主 CTA 和足够视觉上下文。
- 头部、菜单、吸底 CTA、商品卡和表单都能轻松点击和阅读。
- 文案不与图片、按钮、卡片或后续内容重叠。
- 单列商品浏览仍然便于比较核心规格。
- 重要 CTA 不需要过度滚动才能触达。

## 内容与视觉系统

- 各 section 标题结构一致，便于快速扫读。
- 图片展示用户需要判断的真实信息：产品、场景、细节、结果或对比。
- 视觉层级优先服务商业决策，而不是装饰效果。
- 卡片、tab、徽章和按钮尺寸稳定，状态一致。
- 文案具体：产品名、规格、政策条款、使用场景、用户顾虑。
- 全站 H1-H6、正文、按钮、间距系统保持一致。
- 品牌色使用克制且有规律，尤其面向欧美市场。

## 用户反馈与竞品监控

- 已有反馈按问题类型、页面位置、设备、渠道和频次归类。
- 只有“反馈量上升 + 场景丰富”的问题才升级为真实需求。
- 每周或固定周期做业务、产品、设计、开发评审。
- 起步期至少监控 3-5 个同类目直接竞品。
- 成熟期可扩展到 8-10 个跨类目参考。
- 竞品监控记录首屏、CTA、信任、PDP 层级、支付、移动端、产品视频、品牌化、购物车交互和信息密度。

## SEO 与结构化数据

- 页面 title 和 meta description 匹配品类/产品搜索意图。
- 页面只有一个明确 H1，标题层级清晰。
- 图片有有意义的 alt 文案。
- JSON-LD 存在时必须能成功解析。
- 内链可被抓取，锚文本有描述性。

## 埋点与实验准备

- 主 CTA、商品链接、测评/推荐器、表单、导航动作都有 tracking hook。
- 事件命名一致，并能映射到漏斗阶段。
- 区分商业意图点击和普通互动点击。
- 建议对应可衡量指标：CTR、PDP 浏览、加购、开始结账、CVR、AOV、退货率、客服咨询率。
- A/B 测试建议要包含假设、页面位置、目标人群和护栏指标。

## 技术验收

- 核心页面和远程资源返回成功 HTTP 状态。
- LCP、INP、CLS、移动端分数、桌面端分数和页面体积被检查。
- 图片使用合理格式、尺寸和懒加载策略。
- Chrome、Safari、Firefox、Edge 以及 iOS Safari/Android Chrome 关键路径被抽查。
- 慢网络下核心页面仍能完成主要操作。
- 商业路径里没有空链接或占位链接。
- 图片有来源和 alt。
- 必要 section 与 CTA 存在。
- 指定的移动端断点、吸底 CTA 或移动端交互存在。
- tab、测评器、菜单、表单、轮播等交互可用。
- Add to Cart、优惠码、支付流程、邮件确认和转化像素能正常触发。
- 禁用或未验证 claim 不存在。

## 综合排序

- 每个问题都按影响面和修复难度分级。
- 高影响低难度标为立即修复，作为 Quick Wins。
- 高影响高难度标为优先排期，作为重点项目。
- 低影响低难度标为顺手修复。
- 低影响高难度标为暂缓或放弃。
- 每条建议都包含位置、设备、问题描述、数据依据、证据、建议方案、责任归属、优先级和预期指标。
- 责任归属明确到 UI、运营、营销/BM、产品、开发、用户运营或数据分析。
