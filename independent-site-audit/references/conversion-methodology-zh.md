# 独立站转化问题诊断方法

用于需要数据、反馈和页面证据共同解释问题的任务。范围由用户目标决定，按需展开，不强制全漏斗、多部门或固定天数。核心是把“看到什么”与“为什么可能影响购买”分开，再提出能实施、能检查的改法。

## 1. 从可用资料开始

先检查 PostHog、GA4 或后台是否已连接当前 AI，且能读取正确站点的相关数据；已有信息不重复询问。缺少连接时说明可选路线：

| 资料路线 | 可以做什么 | 不能据此声称什么 |
| --- | --- | --- |
| 分析平台或只读后台 | 检查已采集路径、事件、订单或商品事实 | 订单不能还原没采集的浏览；一次回放不能代表全部用户 |
| PDF、表格、数据文档、报告或截图 | 使用已有经营和页面表现资料，注明文件、日期、页码/工作表 | 不能补造读不清的数字或用户级路径 |
| 没有任何数据 | 查看真实页面，与有关标杆对照，说明值得先改的地方 | 不能确定真实流失人数、视觉归因或提升比例 |

建议接入现有分析平台或必要后台，但不要求为了开始而同时安装多套服务。只读取本次结论所需内容，不索取账户密码或完整客户明细。缺少数据不阻止独立界面诊断和确定性缺陷修复。

## 2. 有数据时先核对，再解释

记录实际使用的时间范围、时区、统计单位、分母、来源/设备和相关事件定义；只补充对本次结论有用的明细。漏斗应使用可比较的同一群体与统计单位，事件顺序和时间窗口清楚，不能直接相除不相干的聚合数。

- 区分事件代码存在、浏览器已发送、平台实际收到；检查漏采、重复、跨域与重复购买等影响。
- 对照同站、同渠道、相近条件下的历史表现，核对促销、库存、价格或流量变化。
- 渠道跳出与购买下降是调查线索，不能直接归因于按钮颜色、图片大小或信息密度。
- 新客/回访客和手机/电脑差异需结合来源、样本及任务解释，不预设正常比例。
- 技术标准、项目性能预算和业务经验各有不同用途。使用标准时注明当前来源；不要以无来源的跳出率、点击率或评分作统一合格线。

报告摘要用“哪些人在哪一步更难继续”解释；复杂口径放补充说明。样本不足或资料过时时降低结论强度，不填假数据补齐模板。

## 3. 回到实际购买任务

使用 [检测清单](audit-checklist-zh.md)，按当前问题选择：

- **看懂**：页面表达与广告承诺是否一致；产品、价格、价值、政策与主动作能否看清。
- **选定**：导航、商品差异、比较、规格、变体和筛选是否帮助做选择。
- **买顺**：加购、购物车、费用、表单与支付入口是否有阻碍或错误。
- **跨设备可用**：手机和电脑上的阅读、触控、键盘、加载及异常状态是否符合规格。

观察具体状态、复现动作并保存截图。市场适配检查实际语言、币种、支付、配送和受众需求，不用地域审美印象决定版式。静态 Banner 没有动效不构成缺陷；新增内容、固定按钮或动画须解决具体问题。

用户反馈补充场景和原因，不代替复现。单个严重故障足以支持修复，不要求反馈数量持续上涨。价格、优惠、评分、库存和售后承诺单独核对来源。

## 4. 标杆研究用于解释改法

按问题挑选相关直接竞品或跨品类标杆，不规定固定数量、每周监控或全站研究。打开具体页面，记录 URL、日期、地区、视口、状态和真实截图；受阻时说明限制并选可核验案例。

每个案例写清：用户页面现在怎样 → 标杆如何处理 → 哪个机制可借鉴 → 哪些条件不适用 → 建议怎么改。真实页面证据不能用生成图或搜索摘要替代；对方的价格、权益和承诺不能自动转为本品牌事实。

没有任何数据时，这条对照路线仍能产出方案，但增长效果保持待验证。

## 5. 将诊断连接到实施和验证

每项发现使用稳定问题编号，并明确类型：

- **已复现缺陷**：在记录的条件下实际发生，例如按钮失效或数量错误。按证据修复。
- **体验风险**：观察到不清楚、难触达或缺少反馈等问题，说明判断依据。
- **增长假设**：预计某种呈现能帮助选择或下单，说明如何观察或比较，不承诺结果。

按用户影响、证据和工作量排序；允许零问题，不凑数量。一个推荐方案通常足够，有实质取舍再给备选。用 [报告模板](report-template-zh.md) 连接：

```text
问题编号 → 事实与截图 → 建议改法 → 区域/组件/实现位置 → 验收动作 → 结果
```

方案要解释内容顺序、手机/电脑差异、关键状态、事实来源和可操作的验收条件。仅检测就交付方案；需要原型、实现或上线时按主流程继续，不把普通阶段报告设为新审批点。

## 6. 结果和效果分开报告

静态检查、浏览器操作、生产验证分别使用通过、失败、未执行、不适用。静态标记不能证明页面可用；预览通过不能证明生产版本已更新；事件发出不能证明平台正确接收。

上线任务需核对实际目标版本、受影响关键路径和恢复入口。增长判断则需要定义合理的观察或实验方式：比较对象、统计口径、时间条件及可能同时变化的因素。不是每次修复都要做 A/B 测试，也不能仅凭改版前后数字变化宣布因果。

每个实际执行的大节点产出简短报告，先讲做了什么、发现什么、怎么改、依据是什么、还没确认什么。工作周期按任务与数据决定；长期监控仅在用户要求时安排。最终分别说明页面是否完成、线上是否验证、转化效果是否得到证实。
