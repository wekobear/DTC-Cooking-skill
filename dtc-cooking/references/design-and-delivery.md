# 页面设计、实现与可编辑交付

仅在用户要求原型、页面修改或上线时执行。沿用目标站点的品牌、业务和技术约束；采用新组件不意味着重写整站。

## Playbook + HeroUI

设计前读取 [Vibe Designing Playbook](https://alibaba-cloud-design.github.io/vibe-designing-playbook/) 与本次场景有关的内容。以目标、信息架构、核心路径、组件状态、边界和验收形成简明规格，再画页面。官方示例里的控制台密度或风格不直接套入 DTC 营销页。

规格解释每个区块解决哪个购买问题，写明主次动作、内容顺序、排版层级、颜色/间距等语义 token、桌面和手机差异、素材比例及加载/空/错误状态。用触控目标、焦点状态、行宽、内容驱动断点等可执行词，避免只说“高级”“有质感”。

新原型默认参考 HeroUI v3 的组件结构、状态与主题体系。实现前读取当前 quick-start、实际使用组件的文档及必要主题变量，记录项目真实依赖版本；不混用 v2/v3 API，不固定照抄旧依赖要求。

- **采用 HeroUI 的 React 原型或实现：** 按当前官方文档安装并使用 `@heroui/react` 与相应样式，验证与现有项目的兼容性。
- **HTML + Tailwind CSS：** 可以参考或按当前文档使用 HeroUI 样式与 token；需要自己实现并检查表单、弹层、键盘/焦点及错误反馈。不把静态样式声称为完整 React 组件行为。
- **已有站点：** 优先复用现有组件与购物逻辑，将规格映射回实际技术栈。组件迁移影响较大时明确取舍，不默认新建另一套生产站。

只有本次采用 HeroUI 时才做环境预检；既有组件的局部修复不额外安装组件库或配置 MCP。检查 Skill 可读性和 MCP 可调用工具，实际获取一次有关文档或组件信息后才称连接可用。缺少时按当前平台的官方方式配置，在既有安装目录约定内操作，不覆盖其它配置。新增服务器可能需要重载，区分“已配置”与“连接已验证”。MCP 不可用但官方文档可读时，使用官方文档继续；不要捏造工具调用或把 MCP 设成普通页面工作的门槛。

官方入口：[Quick Start](https://heroui.com/docs/react/getting-started/quick-start)、[Agent Skills](https://heroui.com/docs/react/getting-started/agent-skills)、[MCP Server](https://heroui.com/docs/react/getting-started/mcp-server)。

## 先运行网页，再选择编辑方式

完成可查看的网页和关键状态验证后，若偏好尚不明确，询问：

> 你是否使用 Figma，之后是否想自己修改？有 Figma 可按实际连接能力导入设计稿；没有 Figma 但想手动调整，推荐 pen.dev 客户端；也可以直接交付 HTML + Tailwind CSS。

已有选择不重问；Figma 和 pen.dev 为可选支路。选择可编辑稿时说明可保留的内容，不把导入成功当成业务功能完整可用。

### Figma

1. 在 Codex 中先发现 Figma 插件或连接提供的可调用工具；文件夹存在不证明工具可用。缺失时提示安装 Codex 的 Figma 插件或当前平台对应连接，完成后重载再检查。按平台实际能力提供安装入口，不推荐无关插件。
2. 身份检查仅证明登录；读取目标文件证明可访问，写入位置和库使用还需检查具体目标。用户选定此路线后再补齐缺少的文件/页面或创建位置。
3. 若当前工具支持从已渲染网页生成可编辑图层，使用其当前约定捕获选定页面与状态；只有读取工具时，不承诺能导入。工具或权限暂缺时继续代码交付并说明设计稿尚缺哪一步。
4. 用户要求组件化原型时，再补组件实例、变量、Auto Layout 与所需原型交互。图层可编辑、变量绑定、组件实例和交互连接分别读回核验，不能假定 HTML 导入会自动保持全部结构。
5. 保留原稿，在已选范围内写入。交付链接、实际可编辑范围、验证结果和限制。

参考：[Figma 官方网页捕获说明](https://help.figma.com/hc/en-us/articles/40826832449303-Turn-coded-screens-into-editable-design-layers)。能力可能变化，执行时以当前工具和官方说明为准。

### pen.dev

没有 Figma、但希望手动改文字、图片或排版时，推荐 [pen.dev 客户端](https://www.pen.dev/)。按当前官方能力交付网页/HTML、素材及导入说明；用户请求代操作且工具支持时再实际导入、编辑与导出。推荐不等于擅自安装应用。

导出页面接回开发流程后，核对改动、响应式、按钮与购买相关操作。可编辑图层或导出的 HTML/CSS 不证明支付、库存、账户等业务逻辑已保留；记录实际保留和需要补接的部分。

### 直接 HTML + Tailwind CSS

交付可运行的页面、必要素材和简明预览方式，列明模拟功能。根据交付目标处理实际构建和依赖，不把仅有截图或片段的结果称为完整代码。需要对接已有商店时说明实际集成文件和检查结果。

## 设计和实现共用一份验收依据

对照 PRD 检查真实文案与长内容、窄屏/宽屏、素材裁切、加载/错误、触控和键盘、关键选购路径。修复影响本次目标的问题并复查，不按固定轮数或任意分数无限重做。

发生 Figma 或 pen.dev 手动修改时，将变更回写到同一份规格或变更记录，重新检查受影响页面后再交付/发布。截图对比帮助核对视觉，但不能替代真实操作与业务验证。
